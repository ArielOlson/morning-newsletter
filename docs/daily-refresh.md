After a successful complete read, atomically update `config/calendar-snapshot.local.json`:

```json
{"calendars":[{"input":"exact configured URL","checkedAt":"actual ISO scan time","windowStart":"YYYY-MM-DD","windowEnd":"exclusive YYYY-MM-DD","events":[{"id":"stable event id","title":"event summary","start":"ISO timestamp","end":"ISO timestamp","startDate":"YYYY-MM-DD","endDate":"YYYY-MM-DD","allDay":false,"location":"venue or empty","note":"","recurring":false}]}]}
```

All-day dates have an exclusive endDate. Timed endDate is the New York date of end minus one millisecond. Google connector date-only or midnight values without offsets represent all-day events; preserve their dates and use Luxon with America/New_York for timestamps. Offset-bearing times are timed events. Include ongoing multi-day events. Exclude cancellations. Preserve snapshots for unrelated calendars. On failure, leave previous checkedAt unchanged; never replace failed reads with an empty successful snapshot. The refresh accepts a connected snapshot for at most 26 hours and only if it covers the full two-week window, then visibly marks the calendar unavailable. A complete fresh connected scan takes precedence because public feeds can omit private events. Public feeds are the fallback for unavailable or expired connected scans. Use the configured lookAheadDays consistently for both paths; the current 15-day window includes today plus the following fourteen days.

## 2. Packages

### One parcel, one current row

Use `mergePackageEvidence` for scan updates and retain explicit `orderNumber` plus `orderItemKey` when a retailer supplies an item identifier. Match by stable source ID, normalized tracking number (independent of carrier spelling), or an unambiguous merchant/order/item combination. `sourceIds` and `identityAliases` preserve older notices, coverage references and saved choices when a confirmation acquires tracking. Do not remove these aliases on later scans. Do not create separate rows for preparing, shipped and delivered emails about the same parcel. A late shipping email must not regress a delivered parcel.

Different order numbers, exchange/replacement orders, distinct tracked parcels and different unshipped items remain separate. Never merge by merchant name or similar dates alone; investigate ambiguous evidence rather than guessing. Include order numbers in the encrypted display to distinguish legitimate separate purchases. Saved user choices override email stages across all matched aliases, including explicit undo; the latest confirmed choice wins. Daily builds read these choices but never rewrite the private state repository. The browser reconciles old archive payloads too, preserving their dated email evidence.

### Gmail request pacing

Run Gmail calls sequentially across both accounts, with at least 15 seconds between completed calls and the next request. This is an initial working interval, not a claimed Gmail quota. Reuse successful search pages and previously reviewed immutable message IDs within the current scan; read only new evidence, using bounded batches. Continue all required discovery, reference queries and pagination rather than narrowing coverage to save calls.

On `RATE_LIMIT_EXCEEDED`, stop Gmail calls across both accounts. Honor any supplied retry-after value; otherwise wait at least 60 seconds before the single retry. If it succeeds, use at least 30 seconds between the remaining calls. Preserve completed search results privately so a later resume retries unfinished work instead of replaying the entire scan. If the retry fails, preserve the previous successful snapshot and report the incomplete scan. Never mark failed searches empty or advance checkedAt before coverage validation passes. Do unrelated research during cooldowns; do not probe the quota with unnecessary calls or assume that one successful run establishes a permanent limit.

Use every Gmail connection in `config/connections.local.json`. Import `PACKAGE_DISCOVERY_QUERY` from `scripts/package-scan.mjs` and run it exactly for each account. It includes order confirmations, ready-to-ship notices, ordinary “on the way” subjects, returns, cancellations and subscriptions as well as carrier terms. Never filter by Gmail category, unread status, inbox placement or a fixed retailer/domain list: real transactions can be Promotions, archived, read, Shopify mail or Apple private relay.

Paginate every query fully without a total-result cap. If the connector itself truncates a query, do not finalize: split the date window into bounded smaller queries and retain the original broad-query coverage evidence and every result, or report incomplete coverage. Also search exact known tracking/order references, including older unresolved shipments, and investigate merchants Ariel names. Read relevant MIME bodies (HTML fallback when plain text is empty), distinguish transactional evidence from promotions/digital orders/meal receipts, and reconcile each order confirmation with later shipping and cancellation notices. One canceled item must not cancel the remaining shipment. Label creation is not carrier pickup.

Keep a private coverage audit inside `config/deliveries.local.json`: `scanVersion: 2`, plus `scanAccounts: [{account, searches: [{query, complete: true, checkedAt, messageIds}], readIds, reviews: [{messageId, shipmentIds}] }]`. Excluded messages instead require `excludedReason`; keep it minimal and nonsensitive. Every discovered message needs a disposition, and every shipment mapping must point to a retained record supported by a read message. Do not store raw bodies or personal financial notices in this audit. `assertPackageScan` rejects missing accounts, dropped matches, unread shipment evidence, unmatched records and unfinished pagination before refresh/publication. Use `mergePackageEvidence` to preserve existing records while applying newer evidence, and only advance checkedAt after the complete audit passes.

Merge by carrier and tracking number; a split order can have several parcels. Deduplicate merchant and carrier notices for the same parcel. Keep the most recent reliable status; carrier confirmations outrank a retailer's earlier estimate. Preserve unresolved active shipments even if no new email appears. Keep delivered parcels until Ariel explicitly marks Received or Refunded; email delivery and age never prove personal collection. Distinguish label created, shipped, in transit, out for delivery, delayed, delivered, pickup notice, and subscription renewal. An estimated date passing is not proof of delivery or delay. A building pickup notice without a matching tracking number stays a separate notice with explicit uncertainty; never assume it was collected. Keep unknown ETA unknown.

Where practical, check official carrier tracking pages using the found tracking numbers. A blocked page, login, or CAPTCHA is not evidence of a status. Do not bypass restrictions. Only set carrierCheckedAt after obtaining a real status. Otherwise label the update as email-derived and keep a direct official tracking link. Never call carrier data live if only the email was read.

After a complete scan, atomically update `config/deliveries.local.json`:

```json
{"checkedAt":"actual ISO scan time","scope":"Both connected Gmail accounts","shipments":[{"id":"carrier:tracking-number","merchant":"Retailer or item","status":"shipped","updatedAt":"ISO source email time","detail":"Brief factual status","note":"Useful qualification","expectedDate":"YYYY-MM-DD","expectedLabel":"Estimated delivery","carrier":"Carrier","trackingNumber":"number","trackingURL":"https://official-carrier.example/track","emailURL":"Gmail display_url from source"}]}]}
```

Optional itemName is for a known singular item; optional caption is a concise useful update. Keep detail concise because merchant, item, caption, date, and status share the bold first row. Notes and links form the second row; source update time forms the third. Package choices are confirmed in private encrypted GitHub state; daily scans preserve unresolved shipments and stable tracking identities. Omit absent optional fields. For subscription notices, use expectedLabel `Subscription renewal`, not estimated delivery. Exclude door codes, pickup PINs, home addresses, full email bodies, and credentials. A successful scan with no shipments can produce an empty array. A failed scan must not reset freshness or erase earlier records. The website flags scans older than 26 hours; refreshing public feeds never makes email scans look newer.
